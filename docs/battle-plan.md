# バトルの計画

「見ているだけ」のバトルを、「勝手に戦うけど、ここぞで自分が手を出せる」バトルに作り直す計画。
2026-11-12 にしおみずと決め、battle-feel ブランチに置いていたものを、今の構成に合わせて書き直した（2026-11-17）。
今の動きの正本は `docs/spec.md` の「5. バトル」。数値は `src/core/live.ts` の `LIVE`。

## 1. 目指す形

- 時間で進む。それぞれが自分のペースで勝手に攻撃する。ただし攻撃は1つずつ（列に並んで順番に）
- プレイヤーの操作は3つ：**ねらう**（相手をタップ）、**ふく**（味方の効き目を取る）、**技**（たまったら撃つ）
- 攻撃は**からだ**（濃さ）と**あじ**（香り。味ごとの効き目が付く）の2種類。妖怪ウォッチの戦闘のように、誰が何を受けているかが見えて、手を出す理由がいつもある形
- 先頭はない（2026-11-26 にしおみずと決めた。「当たる相手は誰でもいい。先頭みたいなシステムはいらない」）
- 何もしなくても試合は進んで決着する。操作はうまくやると有利になるもの
- 1試合はふつうの速さで1分ほど。速いと感じる人は倍速（2026-11-26。最初は1秒に3回攻撃が飛んで速すぎた）

やらないこと：アイテム、技の選択、レベル上げ

## 3. 計画と今の作りの違い（しおみずに決めてほしいこと）

計画で★（確認待ち）だった点と、作っているうちに計画から変わった点。今の作りは右の列。

| | 計画 | 今の作り | おすすめ |
|---|---|---|---|
| 1. 後ろの2体の攻撃 | ★前衛100%、後衛は援護として50% | 前衛・後衛をなくした（2026-11-26）。3体とも100%で、誰にでも当たる | 決まり |
| 2. 技 | チームで1本のゲージ。満タンで前衛を押すと時間が止まり、**縞を指でなぞる**（出来で1.5〜3.5倍）。1試合2〜3回 | 1体ずつのゲージ。満タンでボタンを押す（3倍）。6秒放っておくと勝手に出る。押した技は今の攻撃が終わってから出る。1試合に両チーム合わせて6回ほど | 友達テストは今の形で。「技を押す」が面白がられたら、縞なぞりを足す |
| 3. 後ろにいる間の回復 | ★しない（まずは単純に） | 後ろがなくなったのでやめた。回復は、うまい子のあじ攻撃（うまみ）だけ | 今のまま |
| 5. 効き目の強さ | （計画になかった） | 8秒、効き目は spec の表のとおり。拭いたあと8秒は拭けない | 友達テストで「ふく」が押されるか見る。押されなければ効き目を強く・長く |
| 4. 挑戦状の相手 | ★相手チームをCPUが動かす（手を出せる試合） | 今までの自動の試合（誰が開いても同じ試合になる） | 友達テストで挑戦状が送られるか見てから |

## 4. 守る決まり

1. **計算は純粋関数**。`src/core/` の中では DOM・時刻・`Math.random` を使わない（`tests/layers.test.ts` と型チェックで弾く）
2. **同じ入力なら同じ結果**。入力は「両チーム・シード・操作の記録」。乱数は `Rng` だけ
3. **体力・ゲージ・コマは整数**。小数は1回の計算の中だけで使い、すぐ丸める
4. キャラの生成（`creature.ts`、`render.ts`、`fixtures/golden.json` の `base` と `withFlavor`）を変えない
5. 画面は、計算が出した出来事（イベント）を映すだけ。画面側で勝敗や数値を決めない
6. 別の言語との一致は求めない。`golden.json` の `battles`（自動の試合5つ）は、自動の試合をやめるときに一緒に外す

## 5. 数値の調整の目安（`npm run balance`）

| 目安 | 今（2026-11-26、攻撃を1つずつにしてから。1000試合） |
|---|---|
| 試合の長さ（ふつうの速さ）：中央値50〜70秒、時間切れ5%以下 | 中央値 68秒、時間切れ 0%（技にためを足してから） |
| 何もしない人が今日の挑戦者に勝つ割合：35〜45% | 41% |
| 技がたまったらすぐ押すだけの人 | 56% |
| 上手い人（相性の良い相手をねらい、効き目はすぐ拭き、技は効く相手に押す）：70〜80% | 73% |

## 6. 友達テストで見ること

`docs/decisions.md` の「前提：友達テストで見ること」。バトルでは、相手をタップしてねらうことに自分で気づくか、「ふく」が押されるか、効き目の札が読まれているかを見る。
