# 今のアプリの中身

いま動いているものを書く。これから作るものは `docs/battle-plan.md`、決めた理由は `docs/decisions.md`。
機能を変えたら、同じPRでここも直す。

最終更新：2026-11-15（`battle-feel` ブランチの内容まで。★は main にまだ入っていない）

## 画面

画面は4つ。`body` の `data-view` で切り替える（ルーターなし）。

### ホーム
- 見出し、スキャナ窓（カメラ映像＋赤いレーザー線）
- 読み方は3つ：「カメラで読む」「写真から読む」、数字の手入力（13桁・12桁・8桁。チェック数字で検証）
- 架空の試し番号3つ
- 棚：読んだロットの一覧（新しい順、最大40）。押すと値札を再表示
- 棚に1体でもいれば「今日の挑戦者と戦う」。挑戦状のURLで来た人には「挑戦状を受ける」
- `#debug` を付けると「時間を1日すすめる」「記録を消す」

### 誕生
- 読むと、まず商品の中身を調べる（下の「商品の中身」）。そのあと変身演出
- 変身演出（約2.9秒。動きを減らす設定の端末では省略）
  1. 値札ラベルにバーコード、レーザーが2回光る（ピッ）
  2. ラベルがはがれる
  3. 普通の棒24本が体の縞へ、長い棒6本が頭の飾りへ飛ぶ
  4. 体がふくらみ、棒が縞に変わり、顔が出て、跳ねて首をかしげる
- 値札：味、バーコードの種類、名前、何から生まれたか（例「ぶどうから生まれた、かわいい系」）、技、能力4つ（品番からの差つき）、バーコード、ロット番号
- 状態表示：はじめての品番／新しいロットが入荷／前と同じロット（次の入荷まで◯日）
- 「もう1個読む」「画像にする」（1080×1350のPNG。長押しで保存）

### チーム選び
- 相手の3体が見える。棚から3体えらぶ（えらんだ順に前に立つ）
- 組み合わせ技が成立していれば名前を予告
- 「この順番で戦う」「このチームで挑戦状を送る」（共有メニュー、なければURLをコピー）

### バトル
- 上が相手、下がこちら。前に立つ1体が中央で大きく、後ろの2体は小さい ★
- 自動で進む。操作は「結果まで飛ばす」と音のオン・オフだけ
- 演出 ★：ためて体当たり → 当たった瞬間に止まる → 相手が白く光ってのけぞる、画面が揺れる、縞がはじける、数字が跳ねる。技名は中央に値札で出る。体力ゲージは黄色がすぐ減り、赤が遅れて追う。開始・組み合わせ技・勝敗で帯が横切る。倒れたら次の子がすべって前へ
- 効果音 ★：音源ファイルなし（その場で鳴らす）。Androidは当たると振動
- 結果：勝ち／負け／引き分け。「チームを組み直す」「棚にもどる」

## キャラの決まり方

- **品番から**（全国共通で固定）：系統（かわいい／かっこいい）、味6種、色（味ごとに3種）、体形（超楕円）、耳、縞の入り方（お腹のラベル／全身／帯／背中）、目、口、腕、名前（2〜3音。「モ」は使わない）、技、能力の基準値（内容量・濃さ・キレ・コク、各40〜88）
- **ロットから**（個体差。控えめ）：色味のずれ±9°、首のかしげ±6°、キラ目、ほっぺ、シール、能力±8
- 縞はそのバーコードの本物の並び（EAN-13の30本、95モジュール）
- 8桁（EAN-8）と12桁（UPC-A）は13桁に直して扱う

### 商品の中身
- Worker の `/api/product/:jan` が、Yahoo!ショッピング（IDがあれば。**未設定**）→ Open Food Facts の順に調べる
- 返ってきた商品名・カテゴリの文字を、味の辞書（30種。ぶどう、コーラ、カレー、コーヒーなど）に照らす。AIは使わない
- 当たれば、味・色・技をその辞書のもので上書きする（姿・名前は変わらない）。当たらなければ品番から決めたまま
- Worker が返すのは分類のIDだけ。商品名・ブランド名は返さない・保存しない。応答は30日キャッシュ
- 一度決まった分類は端末に保存し、あとから結果が変わってもキャラは変えない

## ロット
- 同じ品番から新しいロットが出るのは、前のロットから一定の日数が過ぎてから
- 試作ではバーコードの種類で日数を決める：通常3日、お店のラベル（先頭02・20〜29）1日、本・雑誌7日
- 期間内にもう一度読むと、前と同じロットが出て「次の入荷まで◯日」と表示する

## バトルの計算（今のもの）
- 体力＝内容量×3（単位はml）、攻撃＝濃さ、素早さ＝キレ、守り＝コク
- ラウンド制。行動順はキレ順（少し乱数）。攻撃は相手の先頭へ
- 味の輪：あまい→からい→うまい→すっぱい→にがい→しょっぱい→あまい。有利なら1.5倍（理由を実況）、不利なら0.75倍
- 組み合わせ技8種（晩酌コンボ、おやつタイム、ジャンクの誘惑、まろやか救済、いちごミルク、レモンスカッシュ、おにぎり定食、フルーツポンチ）：入った体の濃さ1.25倍
- 3体とも同じ味なら守り1.2倍
- 12ラウンドで決着しなければ、残りの量の割合で判定
- 相手：「今日の挑戦者」（日付で決まるCPUの3体）か「挑戦状」（`?vs=` に相手チームの品番・ロット・味を入れたURL。サーバーなし）
- 分かっている弱点：攻撃が相手の先頭に集中する。今日の挑戦者が強め。始まったら見ているだけ → `docs/battle-plan.md` で作り直す

## 保存しているもの
- 端末（localStorage）：ロットの記録、品番ごとの商品の分類、音の設定
- サーバー：なし（Workerのキャッシュだけ）。ログインなし

## 答え合わせ
- `fixtures/golden.json`：決まった50個の番号のキャラ（各3ロット）、味ごとのキャラ30件、バトル5試合
- テスト15件（キャラの一致、バーコードの計算、味の辞書、バトル）

## まだ無いもの
限定パッケージ、発見ゲーム（全国で第一発見者）、オンライン対戦、ログイン、課金、入荷の通知、刻印ボーナス（賞味期限の読み取り）、人が描いた本番のキャラパーツ、決まったタイトル
